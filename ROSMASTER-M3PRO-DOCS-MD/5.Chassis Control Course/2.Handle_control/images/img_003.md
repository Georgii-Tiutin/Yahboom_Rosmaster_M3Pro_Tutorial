## Caption
ROS2 node graph showing the joystick (handle) control data flow from /joy_node through /joy_ctrl to /YB_Node via multiple topics.

## Description
This is a ROS2 computation graph (rqt_graph style) illustrating the node and topic architecture for joystick/handle control of the robot. The flow is left to right:

- /joy_node (ellipse, ROS2 node) publishes to the /joy topic (rectangle).
- /joy topic feeds into /joy_ctrl (ellipse, the joystick control node).
- /joy_ctrl publishes to three topics (rectangles): /beep (for buzzer control), /arm_joint (for robotic arm joint commands), and /cmd_vel (for chassis velocity commands).
- All three topics (/beep, /arm_joint, /cmd_vel) are subscribed to by /YB_Node (ellipse), which is the main Yahboom hardware interface node that communicates with the STM32 control board.

Nodes are represented as ellipses and topics as rectangles, following standard ROS2 graph conventions. The diagram shows how a single joystick input is decomposed into separate control channels for the buzzer, robotic arm, and chassis movement.
