ROS2 communication architecture diagram showing topic, action, and service message passing between three nodes.

## Description
The diagram illustrates the ROS2 communication model with three nodes (Node A, Node B, and Node C) and the three primary communication patterns:

1. **Topic (Publish/Subscribe)**: Node A has a Subscription that receives messages from a Topic. The Topic displays sample output from 'ros2 topic echo' showing timestamped messages with stamp and frame_id fields. Node B also has a Subscription connected to the same Topic. Node C acts as a Publisher sending Messages to the Topic.

2. **Action (Client/Server)**: Node A contains an Action Server, while Node C contains an Action Client. The Action communication involves four message types shown with arrows: Action (request), Goal, Feedback, and Result flowing between the client and server.

3. **Service (Client/Server)**: Node B contains a Service Client, and Node C contains a Service Server. The Service communication shows Request and Response arrows between them.

The layout uses green boxes for nodes, darker green/teal boxes for communication components (Subscription, Publisher, Action Client/Server, Service Client/Server), and a black terminal-style box showing the topic echo output. This diagram serves as a conceptual overview of ROS2 custom interface messages, showing how different message types are used across the three communication paradigms.
