## Caption
Comparison of four communication models used in distributed systems: Peer-to-Peer, Broker, Broadcast, and Data-centric, highlighting DDS as the data-centric approach used in ROS2.

## Description
The image presents a four-column comparison diagram of distributed communication models relevant to robotics middleware selection.

From left to right:
1. **Peer-to-Peer model** — Shows a mesh network topology where nodes connect directly to each other. Associated protocols listed below: TCP, REST, WS*, OPC UA, CORBA, Thrift.
2. **Broker model** — Depicts a hub-and-spoke topology with a central broker node mediating all communication between clients. Associated protocols: MQTT, XMPP, AMQP, Kafka.
3. **Broadcast model** — Illustrates a bus-based topology where messages are sent to all nodes on a shared medium (shown with industrial/fieldbus imagery). Associated protocols: Fieldbus, CANbus, OPC UA Pub-Sub.
4. **Data-centric model** — Shows a shared data space (labeled 'Shared Data Model' and 'DataBus') where multiple participants read and write to a common logical data layer. The associated protocol is DDS (Data Distribution Service), which is highlighted as the communication middleware used by ROS2.

Each model is illustrated with both a real-world photo at the top (network infrastructure, server room, industrial equipment, military/autonomous vehicles) and a schematic diagram below showing the topology pattern. This diagram serves as an introduction to why ROS2 chose DDS as its underlying communication framework, contrasting it with alternative approaches.
