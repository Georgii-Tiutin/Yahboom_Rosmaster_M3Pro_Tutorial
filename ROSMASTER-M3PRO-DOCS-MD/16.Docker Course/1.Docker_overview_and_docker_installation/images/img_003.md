## Caption
Docker architecture diagram showing the client-server model with the Docker client, Docker Host (daemon, containers, and images), and Registry components.

## Description
This diagram illustrates the Docker architecture with three main sections arranged left to right:

1. **Client** (left): Shows three Docker CLI commands — 'docker build', 'docker pull', and 'docker run' — represented as the user-facing interface that sends requests to the Docker Host.

2. **DOCKER_HOST** (center): The main server component containing the Docker daemon at the top. Below the daemon are two groups:
   - **Containers**: Depicted as multiple stacked container icons (blue/teal colored boxes), representing running instances of Docker images.
   - **Images**: Shown as layered stack icons, representing the stored Docker images available on the host. Arrows connect containers and images, indicating that containers are created from images.

3. **Registry** (right): Shows a remote Docker Registry (with an NGINX example image visible), which is the external repository from which images can be pulled or to which they can be pushed.

Arrows flow from the Client commands to the Docker Host, and between the Docker Host and the Registry, illustrating the communication flow. This is a standard Docker architecture overview diagram used in tutorials to explain how Docker's client-server model works, where the client issues commands, the daemon manages containers and images, and registries store and distribute images.
